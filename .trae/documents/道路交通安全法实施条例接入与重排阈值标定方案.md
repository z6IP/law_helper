# 道路交通安全法实施条例接入 + 重排阈值标定方案

## 1. 摘要

用户反馈：对「左转和直行相撞怎么判」这类责任划分问题，本助手的回答明显弱于通用 DeepSeek（后者能引用《道路交通安全法实施条例》中「转弯让直行」规则）。

经实证诊断（用该 query 跑通真实检索 + 重排），定位到两个问题：

1. **根因——语料缺法规**：当前向量库只有《中华人民共和国道路交通安全法》（124 条）+《道路交通事故处理程序规定》（114 条），**缺少《中华人民共和国道路交通安全法实施条例》**。「转弯让直行」只规定于实施条例第五十一条、第五十二条，导致检索命中不了核心规则，只能召回「事故事后处理程序」等弱相关条文。
2. **放大器——重排阈值失配**：当前 `bge-reranker-base` 对弱相关条文仍给出 0.2~0.63 分，`rerank_min_score=0.2` 几乎不过滤（实测 10 条候选有 5 条过阈值），使本应「依据不足拒答」的场景被硬答跑偏。配置注释里的「无关 0~0.04 / 相关 >0.5」对应旧模型 v2-m3，与当前 base 不符。

方案：先补入实施条例语料（用户提供文件），再针对 base 模型重新标定重排阈值。

### 4.2 重排阈值重新标定（保留 base）

1. **一次性标定（实现期执行，不落地为永久脚本）**：补入实施条例后，用标注样本实测 base 分数分布：
   - 正样本（应通过）：责任划分类 query ↔ 实施条例第五十一/五十二条、道路交通安全法第四十四/七十六条。
   - 负样本（应剔除）：同一 query ↔ 程序规定第一百/三十五条；另加无关 query（如「今天天气」）↔ 任意法条。
   - 输出各组分数，阈值取「最低正样本分」与「最高负样本分」之间能最大化召回且剔除程序性噪声的值。
2. **落地 config 变更**：据标定结果更新 [config.py](file:///c:/Users/19674/PycharmProjects/law_helper/app/config.py#L42-L43) 的 `rerank_min_score`，并**同步修正注释**（删除「0~0.04 / >0.5」这类 v2-m3 分布描述，改为 base 实测分布）。
   - 初始预期值 ≈ `0.5`（实测程序性弱相关集中在 0.42~0.63，真正规则条文预期 ≥0.6，待补语料后实测确认）。

> 说明：阈值只能剔除「明显无关」，无法替代「缺失语料」。补语料后实施条例第五十一/五十二条应能排到最前并获得更高分；若标定后发现 base 分数几乎无区分度，则需回退方案（如仅保留 top1~2 或调整召回策略），此点留待标定数据验证。
